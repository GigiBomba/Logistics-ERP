## Goal
Complete architecture cleanup: service-layer extraction from UI, horizontal utility extraction, state management, and removal of all inline business logic from UI files.

## Constraints & Preferences
- ALL 22 language files must match ro.json exactly — 432 keys, identical placeholders, no nulls
- Fuel prices must be live (API), cached, async, country+currency aware, with offline fallback
- No hardcoded fuel prices ANYWHERE in the codebase
- Database tables and existing data must NOT be removed
- UI must only display data from OperationsEngine — no calculations in widgets
- New Operations Engine must be event-driven (no polling, no recursive refreshes, no heavy timers)
- Trip statuses must update AUTOMATICALLY via lifecycle (Planned→Assigned→Loading→In Transit→Delivered→Invoiced→Paid→Archived) with admin override
- Dashboard must NEVER calculate alerts itself — only query OperationsEngine.get_active_alerts()

## Key Decisions
- **Event bus IS the central nervous system** — engine components communicate ONLY through events, never call each other directly
- **Alert evaluation is TRIGGERED by events**, never by polling — `DAILY_CHECK` or `TRUCK_UPDATED` fires re-evaluation
- (removed unused `models/` — codebase uses raw dicts via Repository/Service layers, which is the established pattern)
- **Repository pattern** (`repositories/`) centralizes DB access — DatabaseManager remains the underlying mechanism
- **AppState singleton** replaces scattered module-level state — use `subscribe()` for reactive UI updates
- **Error handler** (`services/error_handler.py`) provides single import for error handling — UI uses `handle_exception(show_dialog=True)`, services use `AppError` with categories
- **Everything in `utils/`** extracts duplicated helper functions — never duplicate formatting/date/validation logic
- **Maintenance engine** still uses direct `conn.execute()` for truck health queries — acceptable since it needs specific column projections
- **FuelPricePanel** in `ui/widgets/` is the first reusable widget — pattern for extracting other self-contained visual components
