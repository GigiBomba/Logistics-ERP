### C4: DriverTruckService Batch Driver Name Query

**File**: `repositories/driver_truck_assignment_repository.py` (lines 82–95)

**New method**: `get_driver_names_for_trucks(truck_ids: list[int]) -> dict[int, str]`

```python
def get_driver_names_for_trucks(self, truck_ids: list[int]) -> dict[int, str]:
    """Return {truck_id: driver_name} mapping for a batch of trucks."""
    if not truck_ids:
        return {}
    placeholders = ", ".join("?" for _ in truck_ids)
    rows = self._fetchall(
        f"""SELECT da.truck_id, d.name
            FROM driver_truck_assignments da
            JOIN drivers d ON da.driver_id = d.id
            WHERE da.truck_id IN ({placeholders})
              AND da.active = 1""",
        tuple(truck_ids)
    )
    return {row["truck_id"]: row["name"] for row in rows}
```

**File**: `services/driver_truck_service.py` (lines 484–486)

**New method**: `get_driver_names_for_trucks(truck_ids: list[int]) -> dict[int, str]`
Delegates to the repository method above.

**⚠️ REVIEW NOTE**: The `AND da.active = 1` filter references a column that does not exist in the `driver_truck_assignments` table as defined in `database/schema.py` (lines 424–433). The table has columns `id, driver_id, truck_id, assigned_at`. If the `active` column was added by a separate migration (`_ensure_column`), it will work. If not, this query will fail. **Recommend adding `_ensure_column` or removing the filter.**

**Impact**: Eliminates N+1 query pattern in FleetTab. Previously 100 individual queries, now 1 batch query. Expected 50–100× performance improvement.

### C6: ConflictService Batch Slot Query

**File**: `services/conflict_service.py` (lines 185–205)

**New method**: `get_next_available_slots_for_trucks(truck_plates: list[str]) -> dict[str, str | None]`

```python
def get_next_available_slots_for_trucks(
    self, truck_plates: list[str]
) -> dict[str, str | None]:
    if not truck_plates:
        return {}
    placeholders = ", ".join("?" for _ in truck_plates)
    non_active = ", ".join(f"'{s}'" for s in sorted(NON_ACTIVE_STATUSES))
    rows = self._trip_repo._fetchall(
        f"""SELECT t.plate_number, MIN(trip.end_date) as next_available
            FROM trucks t
            LEFT JOIN trips trip ON t.id = trip.truck_id
              AND trip.status NOT IN ({non_active})
            WHERE t.plate_number IN ({placeholders})
            GROUP BY t.plate_number""",
        tuple(truck_plates)
    )
    return {r["plate_number"]: r.get("next_available") for r in rows}
```

**Impact**: Eliminates N+1 in RoutePlanner truck loading. Previously `get_next_available_slot()` called for each truck, now one batch query for all. Expected 50–100× improvement.

### C13: GeneratorsView — In-place Combo Update

**File**: `ui/views/generators_view.py` (lines 573–594)

**Before**: Trip combo cleared and repopulated on every refresh (`clear()` + loop `addItem()`).

**After**: In-place update using dict comparison:
```python
def _refresh_trip_lists(self) -> None:
    trips = self._trip_svc.get_all()
    current = {self._trip_combo.itemData(i): i for i in range(self._trip_combo.count())}
    new = {trip["id"]: self._format_trip_label(trip) for trip in trips}

    # Remove deleted: items in current but not in new
    for vid in list(current.keys()):
        if vid not in new:
            self._trip_combo.removeItem(current[vid])

    # Add new: items in new but not in current
    for vid, label in new.items():
        if vid not in current:
            self._trip_combo.addItem(label, vid)
```

**Impact**: Typical refresh with no trip changes: 0 widget operations (was `clear()` + N×`addItem()`). Even with changes, only the delta is touched.

## Design Notes

1. **WorkerPool pattern**: All async views use the same 3-method pattern (`_load` → `_fetch` → `_on_loaded`). Consistent across FleetTab, OverviewView, RoutePlanner.

2. **Inheritance inconsistency**: FleetTab and OverviewView inherit `BaseView` but RoutePlanner, FleetTracking do not. RoutePlanner uses `hasattr` duck-typing. This should be unified — all views should inherit `BaseView`.

3. **Skeleton coverage**: Only views that inherit `BaseView` get skeleton support. RoutePlanner and FleetTracking would benefit from it.

4. **Staleness coverage**: BaseView staleness (30s default) is used by FleetTab and OverviewView. Analytics and ClientWorkspace have their own staleness (300s). FleetTracking doesn't have staleness.

5. **Batch query `active` column issue**: `get_driver_names_for_trucks` references `da.active = 1` which may not exist in the schema. See ⚠️ note in C4 above.
